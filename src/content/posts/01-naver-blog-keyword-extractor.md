## 프롤로그: "글 하나 쓰는데 키워드 찾는 데만 1시간?"

블로그를 시작하는 이유는 사람마다 다릅니다. 소소하게 부수입을 얻어보고 싶어서 시작하기도 하고, 내가 경험한 일이나 생각들을 차분히 정리해 두고 싶어서 열기도 합니다.

이유가 무엇이든 글을 몇 편 쓰다 보면 결국 같은 고민에 부딪히게 됩니다.

기껏 시간을 들여 정성껏 작성했는데 아무도 읽어주지 않으면, 허공에 대고 혼잣말을 한 것 같아 금세 지치고 맙니다. 꾸준히 글을 올리려면 내 글을 읽어주는 사람이 있어야 하고, 사람이 들어오려면 검색 결과 어딘가에는 내 글이 보여야 합니다. 

자연스럽게 **'키워드'**를 찾아보고 공부하게 되는 이유입니다.

하지만 정작 키워드를 찾으려고 컴퓨터 앞에 앉으면 금세 피로해집니다.

1. 키워드 검색 사이트를 열어두고 머릿속에 떠오른 단어를 하나 검색해 봅니다.
2. 검색량과 문서 수를 확인합니다.
3. 내 블로그 지수로는 도저히 들어갈 틈이 안 보여서, 다른 연관 단어로 바꿔 다시 쳐봅니다.
4. 쓸 만해 보이는 단어가 나오면 엑셀이나 메모장에 옮겨 적습니다.
5. 이 과정을 단어마다 계속 반복합니다.

글을 쓰고 생각을 정리하는 시간보다, 웹 브라우저 창을 수십 번 왔다 갔다 하며 검색량 숫자만 확인하는 시간이 훨씬 길어졌습니다.

**"글에 집중해야 하는데, 왜 매일 이 단순한 확인 작업을 손으로 반복하고 있지?"**  
매일 겪는 이 비효율을 그냥 두고 보기 어려웠습니다. 코드로 자동화해서 몇 초 만에 정리해 두기로 했습니다.

## 내가 쓰려고 정리한 3가지 기준

시중에 나와 있는 키워드 플랫폼들도 훌륭하지만, 매월 구독료를 내야 하거나 웹 화면에서 한 번에 한 단어씩 조회해야 하는 구조는 여전히 손이 많이 갔습니다. 제가 매일 쓸 도구였기에 필요한 기준은 단순했습니다.

1. **시드 단어 하나로 연관 키워드를 알아서 확장해 올 것**  
   예를 들어 '어린이대공원' 하나를 넣으면, 네이버 알고리즘이 묶어주는 연관 키워드 수백 개를 자동으로 한 번에 모아와야 했습니다.
2. **검색량뿐 아니라 '경쟁 수준'을 한눈에 보여줄 것**  
   검색량만 높다고 좋은 게 아닙니다. 대형 인플루언서들이 장악한 대형 키워드 대신, 검색량은 꾸준히 나오면서도 내 글이 들어갈 자리가 있는 '실속 있는 세부 키워드'가 직관적으로 보여야 했습니다.
3. **결과물이 내 컴퓨터 엑셀(.xlsx) 파일로 바로 저장될 것**  
   화면에 떴다가 사라지는 데이터가 아니라, 엑셀 시트로 깔끔하게 떨어져서 글감 메모장처럼 두고두고 열어볼 수 있어야 했습니다.

## 파이썬으로 구현한 핵심 흐름

### 1. 네이버 공식 검색광고 API 연동
불안정한 웹 크롤링 대신 네이버의 공식 Search Ad API를 사용했습니다. API 명세에 맞춰 `HMAC-SHA256` 서명 기반 인증 모듈을 작성하고, 네이버가 직접 집계하는 정확한 월간 PC/모바일 검색 수와 클릭 지표를 끌어왔습니다.

### 2. 연관 키워드 확장 탐색
입력한 단어의 1차 연관 키워드를 수집한 뒤, 그중에서 유의미한 키워드들을 다시 파생 검색어로 넘기는 확장 루프를 돌렸습니다. 이미 수집된 단어는 중복 제거하여 API 호출을 아끼면서도, 단어 하나로 수백 개의 세부 키워드 맵이 자동으로 완성되도록 했습니다.

### 3. 실전용 경쟁 지수 계산 및 서식 적용
수집된 데이터에 경쟁 비율을 계산하는 공식을 얹었습니다.
* 검색량은 일정 수준 이상 나오면서 누적 발행 문서 수가 비교적 적은 단어
* 모바일 검색 비율이 높아 스마트폰 사용자 유입이 기대되는 단어

이런 키워드들이 한눈에 띄도록 `openpyxl` 라이브러리를 통해 엑셀 셀에 자동으로 하이라이트를 적용했습니다.

## 직접 써보며 달라진 점 (실제 동작 영상)

완성된 프로그램을 실제 블로그 글을 기획할 때 사용해 보았습니다.

가장 크게 달라진 건 **'시간과 피로감'**이었습니다. 웹 사이트에서 단어 하나씩 쳐보며 1시간 가까이 소모하던 작업이, 단어 하나 입력하고 엔터를 치면 **10~20초 만에 엑셀 파일 하나로 정리**되어 끝났습니다.

키워드 찾는 노가다에 쏟던 에너지를 글의 내용과 사진을 다듬는 본질에 온전히 쓸 수 있게 된 점이 가장 만족스러웠습니다.

## 마무리: 필요한 도구는 직접 만들어서 씁니다

처음에는 온전히 제가 블로그 글을 쓸 때 겪는 번거로움을 덜어내려고 만든 도구였습니다.

하지만 블로그를 운영하시는 분들이라면 부수입을 목적으로 하든 개인 기록을 남기든, 키워드를 찾느라 시간과 에너지를 뺏기는 비슷한 답답함을 한 번쯤 겪으셨을 거라 생각합니다. 

파이썬 설치나 개발 환경 설정 없이도 누구나 윈도우에서 더블클릭 한 번으로 편하게 쓰실 수 있도록, 작은 GUI 창을 얹고 단일 실행 파일(`.exe`)로 정리하여 크몽에 올려두었습니다. 매달 나가는 구독료 없이 내 컴퓨터에 두고 편하게 돌릴 수 있는 가벼운 도구입니다.

앞으로도 이 공간(`twoneworks.com`)에는 거창한 이론 대신, 일상의 비효율을 줄이기 위해 직접 코드로 풀고 현업에서 검증해 본 도구와 작업 기록들을 하나씩 남겨두려 합니다.
